# AGENTS.md

Инструкции для агента, работающего над этим репозиторием.

## Что это

Мобильное SPA «Poker Night» — раздача фишек из набора, учёт домашних покерных вечеров,
итоги и публичные ссылки. Без бэкенда, всё в браузере, живёт на GitHub Pages.

**Источник правды по требованиям — `docs/SPEC.md`.** План работ — `docs/PLAN.md`.
Если код и спека расходятся, прав код только после согласования; иначе правь код.

## Как работать

- Многошаговая задача — создай goal (`create_goal`) и доводи её до конца:
  пока goal активен, DSH сам продолжает сессию, и тебе не нужно ждать
  «продолжай» от человека.
- Не заканчивай ход анонсом («Теперь сделаю…», «Проверяю гейты перед…»).
  Либо вызов инструмента, либо действительно готовый результат. Анонс без
  действия — это брошенная работа.
- `todo_write` обновляй на каждой границе шага: ровно один `in_progress`,
  остальные `completed`/`pending`. Список шагов из `docs/PLAN.md` — единственный
  видимый человеку прогресс, и он не должен отставать от реальной работы.
- Не останавливайся на промежуточном отчёте: отчёт допустим только как часть
  работы, вслед за ним в том же ходу должен идти следующий шаг.

## Команды

```bash
pnpm install
pnpm dev          # vite dev server
pnpm build        # production build в dist/
pnpm preview      # локальный просмотр сборки
pnpm typecheck    # tsc --noEmit
pnpm test         # vitest run
pnpm test:watch   # vitest в watch-режиме
pnpm lint         # biome check
pnpm format       # biome format --write
```

Перед завершением любой задачи все четыре должны быть зелёными:
`pnpm typecheck && pnpm test && pnpm lint && pnpm build`.

## Конвенции

### TypeScript

- `strict: true`, `noUncheckedIndexedAccess: true`. Не отключать.
- Никакого `any` в публичных сигнатурах. Внутри — только с комментарием-обоснованием.
- Предпочитать `type`, а не `interface`, для union-ов и производных типов.
- Чистая логика — в `src/core/**`, без импортов Preact, DOM и `idb`.

### Файлы и именование

- Компоненты — `PascalCase.tsx`, всё остальное — `kebab-case.ts`.
- Один экран — один файл в `src/screens/`.
- Экспорт по имени, не `default` (кроме ленивых чанков, если появятся).

### Стили

- Только CSS: `src/styles/tokens.css` (переменные) + `src/styles/app.css` (остальное).
- Никаких CSS-in-JS, CSS-модулей и Tailwind.
- Новые цвета — только через переменные из `:root`.
- Классы — короткие, по BEM-подобной схеме: `.player`, `.player__name`, `.player--out`.

### Зависимости

Список разрешённого — спека §2.1. **Не добавлять** ничего без явного согласования:
анимационные библиотеки, state-менеджеры, роутеры-пакеты, Workbox, brotli-энкодеры,
альтернативные UI-киты. Если кажется, что зависимость нужна, — сначала напиши, что
именно не получается сделать нативными средствами.

Иконки — `lucide-preact`, импортировать **только** используемые:
```ts
import { Plus } from 'lucide-preact/icons/plus';
```
Не импортировать корневой модуль пакета — он тянет все 3800 иконок.

### Тесты

- Приоритет — `src/core/**`. Каждая чистая функция покрыта.
- UI-тесты не пишем (нет jsdom-инфраструктуры в плане).
- Golden fixtures из спеки §4.7 — обязательны, менять их нельзя без изменения спеки.
- Тесты детерминированы: никаких `Date.now()` внутри без инъекции.

### Числа

- Фишки — целые. Монеты — целые сотые (`CoinCents`). Никогда не хранить деньги как float.
- Форматирование — только через `core/money.ts`.

## Запреты

- Сетевые запросы в рантайме (кроме загрузки приложения и SW-обновлений).
- Хранение производных величин в IndexedDB: только журнал событий и настройки.
- `localStorage` — не использовать, всё в IndexedDB.
- `innerHTML` с пользовательскими данными.
- Логирование персональных данных в консоль.

## Деплой

- Ветка `main`, GitHub Actions → `actions/deploy-pages`.
- `base: '/poker-night/'` в `vite.config.ts` — не менять без смены имени репозитория.
- URL: `https://regulyarniy.github.io/poker-night/`
- `public/404.html` обязателен: без него прямые ссылки `/share/...` дают 404.

## Известные ограничения

- Одна вкладка за раз. Две вкладки перетирают данные; синхронизации нет (спека §12.6).
- Только русский язык, только тёмная тема.
- Brotli-энкодинг ссылок не используется (нет в Chrome). Декодирование — есть.
- Мультивкладочность, экспорт/импорт базы, аккаунты — вне области (спека §1.2).

## Стиль общения в UI

Без глаголов и обращений: «Игроки», «Стек», «Банк», «Итоги», «Начать игру».
Ошибки — короткие существительные: «Дубликат имени», «Нет места».
